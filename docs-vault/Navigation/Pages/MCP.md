# Подключение MCP

Эта страница — справка пользователю. Документация для агентов — только на
английском: `Mcp/AGENT.md` и ресурсы MCP. Агенту достаточно схем инструментов;
справочник загружается по необходимости.

z3nDash предоставляет нативный MCP-сервер через stdio: `z3nDash.exe --mcp`.
Python, Node.js и отдельный MCP-сервер устанавливать не нужно.
Обычный экземпляр обновлённого z3nDash должен уже работать.

## Подключение

В настройках MCP-клиента укажите абсолютный путь к установленному EXE:

```json
{
  "mcpServers": {
    "z3ndash": {
      "command": "C:\\Apps\\z3nDash\\z3nDash.exe",
      "args": ["--mcp"]
    }
  }
}
```

Замените путь на свой. Порт берётся из `.runtime/mcp.json` рядом с EXE;
это фактический порт панели, включая резервный. Для явного выбора экземпляра
добавьте `--api-url`, `http://localhost:ВАШ_ПОРТ`. Допустим только loopback.
Для доступа только на чтение добавьте `--read-only`: команды изменения исчезнут.

## Работа

При проблемах подключения используйте `get_status`. Краткий английский контракт
доступен через `read_document` с `topic=mcp`.
`list_tasks` находит ID задач, `get_task` возвращает настройки и `_revision`.
Для изменения/удаления передавайте эту ревизию; конфликт требует перечитать задачу.
`run_task` ставит реальные прогоны в очередь; проверяйте исполнение через
`list_task_runtime` и `read_task_output`. Пауза и отсрочка сохраняются между
перезапусками, уже работающие экземпляры продолжают работу.

`list_nodes` возвращает сохранённые подключения [[Remote Tasker]]. Их ID
передаётся как `node`; по умолчанию используется `local`. Ключи агенту не выдаются.
MCP управляет Tasker; редакторы БД, терминал и конфигурация с секретами не доступны.

Краткий контракт: `z3ndash://docs/mcp` / `Mcp/AGENT.md`.
Полный справочник и конфигурация TOML: `read_document(topic=setup)`
или файл `Mcp/README.md` рядом с приложением.
Документы [[Task API]] и [[Script agent instructions]] доступны через
`read_document` с `topic=task-api` / `script-agent`, только на английском.
Документация читается и без запущенной панели.

При таймауте команды результат может быть неизвестен. Сначала проверьте состояние;
не повторяйте запуск вслепую. `stop_task` завершает процессы, `delete_task`
удаляет задачу и останавливает её экземпляры; скрипты на диске не удаляются.
