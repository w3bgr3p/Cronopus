# BAS: управление XML-проектами

**Beta в Cronopus 1.2.0.0:** модуль находится в разработке, не полностью протестирован и готов, может содержать ошибки. Пометка Beta относится только к BAS; остальные модули сохраняют стабильный статус.

Откройте **BAS** в доке или `/bas.html`, чтобы запускать сохранённые XML-проекты BrowserAutomationStudio локально или на сохранённых Windows-узлах [[Remote Tasker]]. Premium, публикация в облаке и ручная компиляция не требуются. Предварительная версия доступна в [релизе 1.2.0.0 Beta](https://github.com/w3bgr3p/Cronopus/releases/tag/v1.2.0.0).

## Запуск проекта

1. Выберите **Local** или сохранённое HTTPS-подключение. Подключения настраиваются в **[[Config]] → Remote Tasker**.
2. Нажмите **New**, затем **Choose XML**. Локально откроется диалог Windows, удалённо — файловый браузер выбранного узла с папками и XML-файлами. Путь и предлагаемое имя заполняются автоматически; имя можно изменить. Отмена не меняет текущий выбор.
3. Ресурсы загружаются из XML на выбранном узле. **From XML** обновляет форму после внешнего редактирования файла. Меняйте поля ресурсов; сохраняются только переопределения. **Use XML default** возвращает значение из XML. Исходный файл не изменяется.
4. Сохраните проект и нажмите **Run**. Число потоков и лимиты BAS определяются самим XML.
5. Проверяйте **Runs** и **Log**. **Stop** останавливает дерево процессов этого проекта, не затрагивая другие проекты и редакторы BAS.

У сохранённого проекта одновременно может быть один активный запуск. Разные проекты могут выполняться параллельно. Один процесс запуска не означает один нативный поток BAS.

Поддерживаются переопределения `FixedString`, `RandomString`, `FixedInteger` с объявленными границами, `LinesFromFile` с путём и одиночный `Select`. Варианты Select берутся из `Values`; индекс `Selected` в рабочей копии начинается с нуля. Неизвестные имена ресурсов, необъявленные варианты и неподдерживаемые типы переопределений отклоняются. Остальные типы ресурсов сохраняют исходные настройки XML.

Select с двумя вариантами `true`/`false` отображается переключателем On/Off с управлением кликом или пробелом. Сохраняются исходные строки вариантов BAS. Другие списки остаются выпадающими.

Форма использует `Description`, подсказки, значения по умолчанию, числовые границы, `Visible`, `Enabled`, `IsAdvanced`, многострочность, обязательность и условия видимости ресурсов. Скрытые ресурсы не выводятся, расширенные доступны через **Advanced**; отключённые и неподдерживаемые поля доступны только для чтения. Поля password/token/secret маскируются.

Редактор **JSON overrides** синхронизирован с формой; `{}` означает значения XML по умолчанию. Пустая строка — явное переопределение пустым значением, а не сброс. Save сохраняет форму до того, как Run использует настройки. Смена XML очищает старые переопределения; устаревшие ответы после смены проекта или узла игнорируются.

Ресурсы читаются через `GET /bridge/v1/bas/resources?projectPath=...` на выбранном узле с существующей проверкой ключа и сертификата.

Исходный XML не перезаписывается. Движок получает копию; относительные пути `LinesFromFile` разрешаются от каталога исходного XML. Прямые вызовы `project_path()` в исполняемом коде указывают на исходный XML, позволяя искать родительские каталоги `Essentials` и `data`. Строки, комментарии и метаданные полотна сохраняются. Другие относительные пути зависят от семантики BAS; для внешних файлов используйте абсолютные пути.

## Движок и процессы

При первом запуске по HTTPS скачивается unprotected engine для `EngineVersion` из XML и проверяется SHA-1, предоставленный издателем. Архив и чистый движок кешируются на узле по версии. У проектов отдельные рабочие каталоги; крупные исполняемые файлы используют жёсткие ссылки NTFS, где это возможно, иначе копируются.

Клонирование сохраняет пустые служебные каталоги BAS. Старые рабочие каталоги исправляются при следующей подготовке без повторной загрузки и замены настроек. Отсутствие таких папок может приводить к пустому результату JavaScript в браузере при успешной навигации.

Запускается `FastExecuteScript.exe --silent`. Авторизация опубликованного скрипта, имя функции и Premium control API не используются. Нативные логи, результаты и `bas_reports` сохраняются в отдельный каталог запуска.

**Release runtime** останавливает проект, освобождает его состояние и очищает историю запусков и логов в памяти. Перед редактированием сохранённого проекта освободите runtime. **Delete** доступна без активного выполнения и автоматически освобождает runtime перед удалением записи проекта; исходный XML не удаляется. Кеш движка сохраняется. Изменения исходного XML читаются при новом запуске; смена `EngineVersion` требует освобождения и новой подготовки runtime.

Дерево процессов принадлежит Cronopus через Windows Job Object. Отмена или закрытие панели завершает его. После перезапуска Cronopus прерванные XML-проекты автоматически не возобновляются.

## Результаты и неопределённость сети

**Run** подтверждает принятие команды, а не завершение. Одного кода выхода 0 недостаточно: Cronopus требует нативный отчёт с успешным финальным сообщением и без ошибок. Без отчёта выполнение отмечается как неподтверждённое.

Удалённый запуск использует HTTPS, закреплённые сертификаты, ключи, отзыв доступа и журнал операций [[Remote Tasker]]. Если ответ команды потерян, **Check command** читает исходную запись журнала без повторной отправки. `pending` и `outcome_unknown` не подтверждают ни успех, ни ошибку.

Если доступный узел не содержит записи команды, проверьте запуски и после выяснения результата нажмите **Dismiss pending**. Кнопка очищает только отметку в браузере и не повторяет команду.

Настройки проектов хранятся в закрытом `BridgeStore` с Windows DPAPI. JSON-переопределения могут содержать секреты; события и ошибки маскируют значения ресурсов с password/token/secret в имени. Авторизованный оператор может читать сохранённые переопределения. Содержимое логов выводится как текст, включая строки, похожие на HTML.

История ограничена 250 запусками и 500 событиями на загруженный проект, 16 КиБ на событие и 256 КиБ в браузерном просмотре лога. Нативные файлы хранятся в пределах 30 каталогов запусков и 1 ГиБ на проект. Перед запуском старые каталоги очищаются; выполнение останавливается при превышении 512 МиБ вывода. Отчёты API ограничены 256 КиБ.

Маркеры цвета нативных логов BAS отображаются с учётом темы. Время, поток/тип и сообщение разделены по колонкам; путь исходного файла виден при наведении. Одинаковые последовательные сообщения сворачиваются со счётчиком и временем последнего повтора. Нативные файлы сохраняют полный вывод.

## Интеграция C#

- `BasControlClient`: подготовка XML, владение процессами, чтение логов и проверка нативного отчёта.
- `BasXmlProject`: разбор XML, проверка ресурсов и сохранность исходника.
- `BasControlService`: сохранённые проекты, ревизии, состояния, отмена и ограниченная история.
- `BridgeHost.InvokeBasAsync`: журналируемые команды `/bridge/v1/bas/`; локальная страница использует защищённые `/bridge-local/` маршруты.

## Проверки разработчика

```powershell
rtk dotnet run --project tests/Bas.Integration/Bas.Integration.csproj
rtk dotnet run --project tests/Bas.Integration/Bas.Integration.csproj -- --live
```

Обычный набор использует изолированное хранилище и имитацию выполнения поверх настоящего HTTPS с проверкой сертификата. `--live` запускает безопасный XML-пример в BAS 31.1.0 и проверяет отчёт и неизменность исходника. `CRONOPUS_BAS_TEST_ENGINE` позволяет указать тестовый движок без новой загрузки. Эти проверки не означают полной готовности модуля Beta.

Для проверки браузерного интерфейса запустите набор с `--serve`, затем `rtk python tests/bas_browser.py <BAS_BROWSER_URL>`. Сервер печатает фактический URL, предпочитая порт 39761.
