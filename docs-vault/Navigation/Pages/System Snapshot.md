# System Snapshot

System Snapshot собирает диагностический снимок текущей Windows-системы.

## Обновление

При открытии страницы сбор запускается автоматически на машине, где работает z3nDash. Кнопка `Refresh` повторно собирает актуальные данные. Страница включает секции, которые фактически смог собрать backend: процессы, сеть и системные данные.

Данные страницы находятся только в памяти. Сохранение снимков в БД, история и загрузка из файлов убраны.

## Распределение памяти

Сводка показывает физическую RAM и Windows commit: текущий объём
выделенной памяти, лимит, оставшийся запас и пик с момента загрузки. Рядом указаны
paged и nonpaged пулы ядра. При 90% commit появляется предупреждение, при 97% —
критический статус, даже если свободная физическая RAM ещё есть.

Группы процессов показывают private allocation и резидентную RAM отдельно,
суммируя экземпляры. Недоступные измерения private memory учитываются, чтобы
неполные суммы были видны. AI-аудит получает то же разделение.

Интерактивная карта распределяет площадь блоков по расходу групп процессов.
`Block size` переключает private allocation и resident RAM. Доли рассчитываются
от показанной суммы процессов, а фильтр применяется к карте и таблице.
Резидентные суммы могут повторно учитывать общие страницы; private allocation
процессов не покрывает весь системный commit.

Нажмите блок для списка PID и выберите процесс, чтобы открыть его командную
строку и действия в боковой панели. Измерения обновляются через `Refresh`.

## CPU

Раздел `CPU usage` показывает карту текущей нагрузки по группам процессов
и таблицу с `CPU_PCT`. Измерение идёт за короткий интервал; 100% соответствует
занятости всех логических CPU. `CPU_SEC` — накопленное время за жизнь процесса,
оно не используется как текущая нагрузка.

Площадь блока показывает долю группы в отображённой нагрузке без простоя CPU.
Выбор блока открывает PID, отсортированные по текущему CPU. Непрочитанные
измерения помечаются как недоступные. Сумма процессов может отличаться от
общей нагрузки из-за работы ядра, различий интервалов и завершившихся процессов.

## Environment

Первый пункт левой навигации, не часть снимка. Показывает инструменты машины для
запуска задач: что фактически вернули команда, реестр или подключение. Проверка
занимает несколько секунд, поэтому сама запускается только при первом открытии
раздела, дальше — кнопкой `Check`. Для недостающего инструмента есть кнопка
`Install`: установщик открывается в отдельном окне консоли, по окончании жмут `Check`.

Открытый раздел Environment сохраняется при `Refresh` и при следующем посещении страницы.

## Запись диагностики

На страницах с диагностикой `Ctrl+Shift+D` начинает или завершает запись.
Индикатор записи также предлагает **Report** и **Stop**. Связанные события
браузера и сервера разделяют ожидание в браузере, очередь сервера и обработку
запроса, включая время БД, блокировок планировщика и консоли.

JSONL сохраняется в подкаталоге `diag` настроенной папки логов. При остановке
рядом записывается читаемый `.txt`-отчёт: медленные запросы, время маршрутов и
задержки браузера. SQL-события сохраняют операцию и имя таблицы без значений.

## AI Audit

Опциональный аудит отправляет текущие данные страницы в OmniRoute. Кэш хранится в `system_snapshot_ai_cache`; старый отчёт при открытии страницы автоматически не загружается.

## API

- `POST /system-snapshot/capture`
- `POST /system-snapshot/ai-audit`
- `GET /system-snapshot/ai-cache`
- `DELETE /system-snapshot/ai-cache`
- `GET /config/environment`
- `POST /config/environment/install`
